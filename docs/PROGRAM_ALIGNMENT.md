# ClaimTrace public-case alignment for 15 graduate programs

Checked against the linked official program pages on 2026-08-10. Course names and structures can change. The **official basis** column paraphrases the university page; the **portfolio bridge** column is an applicant-authored inference about how ClaimTrace may be discussed. It is not an admissions preference stated by the school.

ClaimTrace should remain one coherent project: a local-first system for testing whether versioned evidence still supports an analytical claim and its downstream action. The ten cases are supporting demonstrations, not ten unrelated projects.

## Recommended application use

1. Introduce ClaimTrace once: problem, architecture, individual contribution, and verification boundary.
2. Select one primary public case for the target program; add at most one secondary case when it proves a distinct capability.
3. State the exact observed result from the generated audit, then state the decision consequence separately.
4. Name the strongest limitation before proposing future work. This is more credible than presenting every case as a complete empirical study.
5. Present the six public-data studies first; keep the four synthetic cases clearly labeled as adversarial regression fixtures rather than evidence of real-world outcomes.

## Remaining high-value gaps

- A real randomized or quasi-experimental behavioral intervention case would materially strengthen Penn MBDS and HKS fit.
- Interval-aware rules, formal inference, and predictive/model validation would materially strengthen Columbia Statistics and both health-data programs.
- A true asset-allocation or risk-model backtest with transaction-cost and out-of-sample controls would strengthen Yale and Columbia FinTech, but must not be added without real reproducible data and methods.
- A geospatial boundary/network workflow and spatial sensitivity analysis would strengthen Cambridge PGR; the current ONS case is attribute-table analysis only.
